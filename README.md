# Кто перед вами

Тренажёр общения для комьюнити (веб + Telegram Mini App): 9 архетипов. У каждого научное название, трендовое название из соцсетей и источники.

| Архетип | В соцсетях | Научная основа |
|---|---|---|
| Тёмный эмпат | dark empath | Тёмная триада + эмпатия (Heym et al., 2021) |
| Грандиозный нарцисс | нарцисс, love bomber | Модель NARC (Back et al., 2013) |
| Уязвимый нарцисс | скрытый нарцисс, covert | Hendin & Cheek, 1997; Miller et al., 2011 |
| Макиавеллист | манипулятор | Jones & Paulhus, 2014 |
| Психопат | социопат, тролль | Триархическая модель (Patrick et al., 2009) + бытовой садизм (Buckels et al., 2013) |
| Пограничный тип | ПРЛ, «качели» | Kernberg, 1967; ICD-11; тревожная привязанность |
| Избегающий тип | «эмоционально недоступный» | Bartholomew & Horowitz, 1991 |
| Высокочувствительный | эмпат, HSP | Aron & Aron, 1997 |
| Надёжный тип | «зелёный флаг» | Надёжная привязанность (Hazan & Shaver, 1987) + светлая триада (Kaufman et al., 2019) |

- **Архетипы** — карточки на главной, у каждой страница с научной основой, признаками и источниками.
- **Мой тип** — скрининг: 26 утверждений по 13 измерениям, ранжирование по прототипам. Формулировки собственные: валидированные шкалы защищены авторским правом (TAS-20 требует платной лицензии).
| Боль | Решение |
|---|---|
| Манипуляции | **Флаги** — кейсы «кто перед вами» |
| Нет гармонии в общении | **Профайлинг** — диалог с ИИ-персонажем (скрытым или выбранным) и разбор от ИИ-тренера |
| Нет системного взгляда на отношения | **Арена** — эксперименты «кто кого» |

- **Арена** — перетащите двух персонажей в слоты A и B, выберите стадию отношений (знакомство, роман, 3 года вместе) и смотрите их диалог: 10 реплик ИИ против ИИ. У каждого архетипа есть скрытый мотив, его «выигрыш». ИИ-аналитик оценивает, кто добился своего (0–10), и чем кончились отношения. Результаты копятся в матрице 9×9 «кто кого».

Это не диагностика: приложение описывает паттерны поведения.

## Картинки архетипов

Положить `public/img/archetypes/<id>.webp` (портрет 4:5) и добавить `id` в `IMAGES_READY` в `public/js/archetypes.js`. До этого показывается эмодзи на цветном градиенте.

## Запуск

```bash
npm install
AUTH_MODE=off DEEPSEEK_API_KEY=sk-... npm start   # http://localhost:3000, без входа
npm test
```

Без ключа ИИ тест и кейсы работают, а диалоги отключены. `AUTH_MODE=off` отключает вход и проверку подписки (локально и на Render): Профайлинг и Арена открыты всем, действуют только лимиты запросов и `AI_CALLS_PER_HOUR`.

## ИИ-провайдер

| `AI_PROVIDER` | Ключ | Модель | Назначение |
|---|---|---|---|
| `deepseek` | `DEEPSEEK_API_KEY` | `deepseek-flash` | демо, дёшево |
| `anthropic` | `ANTHROPIC_API_KEY` | `claude-opus-5-5` | продакшен |

Переключение — одна переменная окружения, код менять не нужно. Если `AI_PROVIDER` не задан, берётся тот провайдер, чей ключ есть (DeepSeek в приоритете).

## Деплой на Render

1. Render → **New → Blueprint** → выбрать этот репозиторий (`render.yaml` подхватится сам).
2. Ввести `DEEPSEEK_API_KEY`. Поле `ANTHROPIC_API_KEY` пока оставить пустым.
3. Поставить лимит трат у провайдера. `AI_CALLS_PER_HOUR` (по умолчанию 300) — общий лимит ИИ-запросов в час на сервер.

## Аналитика (PostHog)

Браузер шлёт события на `/api/track`, сервер пересылает их в PostHog. Через прокси события не режут блокировщики рекламы, а тексты диалогов в аналитику не попадают никогда: сервер пропускает только события и свойства из белого списка (`src/analytics.js`).

1. Зарегистрироваться на [eu.posthog.com](https://eu.posthog.com) и скопировать Project API key (`phc_...`).
2. Задать `POSTHOG_KEY` в Render. Без ключа аналитика выключена, остальное работает.
3. В PostHog → Settings → Project включить **Discard client IP data**: страна определится, а сам IP не сохранится.

**Воронка:** `app_opened` → `test_started` → `test_completed` → `spar_started` → `spar_completed`. Дополнительно: `archetype_viewed`, `case_answered`, `lab_started`, `lab_completed`.

**Источник трафика** (запоминается первое касание, в PostHog это `initial_source` / `initial_campaign`):
- веб: `https://…/?utm_source=tiktok&utm_campaign=reels1`;
- Telegram: `https://t.me/<bot>/<app>?startapp=tiktok_reels1` (формат `<источник>_<кампания>`).

Для каждого рекламного канала и креатива нужна своя ссылка, тогда CAC считается по каналам.

## Telegram Mini App

@BotFather → `/newapp` (или `/setmenubutton`) → указать URL сервиса на Render. Тема (светлая или тёмная) подхватывается из Telegram.

## Вход и подписка через бота

Доступ: **тест, флаги и карточки — всем**; **Профайлинг и Арена** — участникам канала. Без подписки — 1 пробный Профайлинг и 1 пробная Арена.

| Переменная | Значение |
|---|---|
| `AUTORIZATION_BOT` | Токен бота из @BotFather |
| `TELEGRAM_CHAT_ID` | ID канала или чата, участники которого получают доступ (например, `-1001234567890`) |
| `TELEGRAM_CHANNEL_URL` | Ссылка-приглашение для экрана подписки |
| `SESSION_SECRET` | Случайная строка от 32 символов (Render сгенерирует сам); смена разлогинивает всех |

Шаги:
1. Добавьте бота **администратором** в канал (без прав на публикацию): иначе Telegram не отдаёт ему список участников.
2. Узнайте ID канала: перешлите любой пост канала боту @userinfobot или @getidsbot.
3. Задайте переменные в Render и перезапустите сервис. В логах должно появиться `Telegram webhook set for @<бот>` и `Auth mode: telegram`.

Как работает:
- **В Mini App** вход автоматический: сервер проверяет подпись `initData` от Telegram.
- **В браузере** — «Войти» → сайт показывает двузначный код и ссылку на бота → в боте «Старт» и выбрать тот же код из трёх. Сверка кода защищает от фишинга пересланной ссылкой.
- Сессия — подписанный токен в `localStorage` (30 дней), передаётся в заголовке `Authorization`.
- Подписка проверяется через `getChatMember` и кэшируется на 5 минут; кнопка «Я вступил — проверить» перепроверяет сразу.
- Каждая тренировка начинается с подписанного «билета», без него переписку нельзя продолжить — так пробный доступ не обойти.
- Состояние входа и счётчики проб хранятся в памяти: после перезапуска сервиса пробы обнуляются, сессии остаются.
